# Zero-work and one-rep check-ins

Configured workouts on iPhone offer an explicit **Skip set / stop here** action when no positive rep quantity is recorded, or before a hold timer has recorded active time. A missing manual entry and zero camera observations are not proof that the person did no exercise. The action records a user choice, rather than inventing a completed zero-rep set or treating the target as actual work.

After Skip, the check-in makes **Finish session** the primary action. Continuing to the next existing planned step is optional and explicit; that step still needs Start. There is no automatic additional set, target reduction, or recommendation to keep going. Watch command names are unchanged. An optional backward-compatible skip flag blocks Next set and directs the current Watch app to the iPhone check-in; target adjustment remains on iPhone. Skipping cannot discard a positive entered/observed rep count, an active hold with positive time, or bypass a discomfort stop.

`SessionRecord.skippedSets` stores separate `SkippedSet` metadata: identity, exercise ID, planned set number, target, unit, input source and `reason: userChoice`. Old records decode a missing/null array as empty. Skips persist in local history and JSON exports when the user finishes; they do not enter `sets`/`loggedSets`, completed-set counts, reps, active time or XP. A skip-only session can therefore be saved with zero completed sets. Unended time is not converted into completed work. An unstarted skip preserves the rest interval from the previous ended set. If a skipped attempt was started, the next rest interval begins at the explicit Skip action; time spent attempting the skipped step is not labelled continuous rest.

After one completed rep, the rest screen can offer an explicit choice to make remaining sets of **the same exercise** one rep each. This changes only future targets in the current run. It preserves the queue length, identities, order, units and rest values; the completed set retains its original target and actual quantity. The saved approved plan is unchanged. There is no adjustment while active, after a skip, with no eligible remaining set, or after reported discomfort. Reducing targets does not imply measured ability or physiological readiness.

The existing Tiger contract is unchanged. `WorkoutSyncClient` explicitly projects the original `id`, `date`, `sets`, `telemetry` and `loggedSets` wire shape, omitting local skip metadata. A skip-only record fails locally with an explanation before transport. A mixed session uploads only its completed-set projection, while the complete local history/export retains skips. Cloud skip persistence remains separate. The in-session review distinguishes skips now; the parallel report-polish slice adds a separate reopened-report section and keeps skip-only records local.
