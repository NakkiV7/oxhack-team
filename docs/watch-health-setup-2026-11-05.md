# Optional Apple Health and Watch setup

The six-step introduction now runs welcome → optional Health/Watch setup → goals → personal details → comfortable movements → trainer. Skipping setup preserves all phone features. Setup is repeatable from Profile & settings, Today and Insights; root navigation injects the same `HealthDataStore` instance so zone choices and opt-in state are shared. Restarting the introduction retains that instance and existing profile/history.

`HealthSetupView(store:)` provides an explicit Choose Health data action, refresh, a way to stop showing Health readings, and optional zone settings. `WatchSetupView()` is the standalone installation guide, with navigation title “Watch setup”. Neither view interprets the permission request’s completion as granted read access. Default construction does not query Health or request permission. A previously chosen opt-in is remembered locally so explicit refresh can read again without prompting automatically.

`HealthDataStore` is the native alias for the tested `HealthSnapshotStore`, with a production convenience initializer using `AppleHealthReadingClient`. Its public display API is `snapshot`, `statusMessage`, `isBusy`, `hasRequestedAccess`, `zones`, `connect()` and `refresh()`. A snapshot contains `observations`, `latestObservations`, `dailyObservations`, `asOf`, `dayStart` and `dayEnd`. Each observation has `metric`, `title`, `unit`, `value`, `date` and `source`.

The read-only HealthKit boundary requests only resting heart rate, walking heart rate average, SDNN HRV, VO₂ max, one-minute heart rate recovery, oxygen saturation, respiratory rate, steps and walking/running distance. Latest physiology retains each sample’s actual end date and source; old readings are not live workout measurements. Daily activity is queried independently from local midnight to the read time using `HKStatisticsQuery` with `.cumulativeSum` and merged sources. Watch and iPhone totals are not manually added together. Missing or unshared values remain absent; only a genuine quantity can produce a displayed zero for daily activity.

Both sample and daily-statistics results now pass through one guarded quantity conversion. `quantity.is(compatibleWith:)` is checked before `doubleValue(for:)` so incompatible dimensions are omitted instead of raising a HealthKit exception. Oxygen retains the existing fraction-to-percent conversion (`0.98` becomes `98%`). One-minute recovery uses HealthKit’s count quantity (`18` stays `18`, displayed as an 18-bpm heart-rate drop), following [Apple’s recovery type documentation](https://developer.apple.com/documentation/healthkit/hkquantitytypeidentifier/heartraterecoveryoneminute). It remains positive-only. VO₂ max uses the composed mL/(kg·min) unit. `HealthQuantityConversionTests` uses actual `HKQuantity` fixtures for these three conversions and incompatible-unit rejection. The integrating agent captured the expected missing-helper compile red; all four corrected native quantity fixtures passed in the integrated simulator run.

Health observations remain in memory. They are not written to workout history, local files, a website account or the network. UserDefaults stores only the explicit Health opt-in and optional maximum/estimate flag, isolated under a separate suite for valid `SPOTTR_DATA_NAMESPACE` UI tests. Zone changes are validated through the shared `HeartRateZoneConfiguration` API: finite maximum 60–260 bpm or an explicitly chosen adult age estimate for ages 18–100. There is no default age/maximum, birth-date query, Apple zone inference or target prescription. Disconnecting removes visible readings and rejects late in-flight responses. Current-day snapshots expire at midnight, with a scheduled new-day read and calendar/DST boundaries.

The Watch guide describes the current TestFlight route: install the iPhone beta, inspect App Details for a compatible Watch install/update action, or use Watch → My Watch → Available Apps → Install when Spottr appears. It describes the public Watch App Store route conditionally for release. Connection status reads existing WCSession metadata without replacing its delegate or activating a competing session. Pairing/installation/reachability never claim Health authorization or verified physical sensor behavior.

Focused red/green core verification passed 10 checks on the SSD, covering historical/daily separation, invalid/future/duplicate data, DST, activation-aware Watch status, explicit opt-in, empty/failed reads, unsupported Health, midnight refresh, discarded in-flight responses and local preference persistence. Native Health boundary/zone tests and the skip-setup UI journey are authored for the integrating agent’s build; the Health subtask did not build or operate a simulator. The root agent owns iOS capability/profile/source registration and final native/device acceptance. Real Health permissions, data availability, Watch installation and sensor delivery require device verification.

## Integrated verification

The final shared-core suite passed 125 XCTest and 260 Swift Testing checks (385 total). The existing iPhone simulator passed 220 selected native checks across the integrated run and packaging correction, plus all 13 selected UI journeys after correcting outdated navigation assumptions and querying the visible Health link label. Four pre-existing StoreKit framework cases remain setup-blocked by the simulator’s `notEntitled` response and were excluded explicitly; no purchase acceptance is claimed. Watch SDK doubles passed 12 recorder and 8 store cases; codec and durable delivery replay checks passed. Both signed apps carry HealthKit entitlements and matching distribution profiles. Apple validation initially required the host’s Health-update purpose string because it embeds the workout-saving companion; the corrected archive includes both purpose strings.

Hardware permissions, sensor availability, overnight/background delivery, long-workout battery and physical motion accuracy remain unverified. Snapshot data stays in memory; saved workout telemetry and bounded sync queues stay local. A failed write or a queue exceeding 7,200 packets has an explicit limit, and unflushed samples can be lost on termination. The app does not reconstruct an unfinished phone workout after a crash.
